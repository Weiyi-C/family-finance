## 1. notify — 提醒通知

**设计意图**：条件触发推送通知，不修改数据。

**触发时机**：定时任务（每小时或每天），扫描 transactions / credit_card_bills / budgets 表。

**规则条件（conditions）**：
```json
{
  "type": "budget_exceed",       // 预算超支
  "threshold": 0.8,              // 预算使用比例阈值
  "category_name": "餐饮"        // 可选，指定分类
}
{
  "type": "large_expense",       // 大额支出
  "amount_min": 500000           // 最小金额（分）
}
{
  "type": "bill_due",            // 账单还款提醒
  "days_before": 3               // 提前几天
}
{
  "type": "no_transaction",      // 连续无记录
  "days": 7                      // 连续天数
}
```

**规则动作（actions）**：
```json
{
  "notify_title": "预算预警",
  "notify_content": "{category}支出已达预算的{percent}%",
  "notify_type": "budget_alert"
}
```

**新增依赖**：
- notifications 表（已有）
- scheduler.py 定时任务（已有框架，需扩展）

**数据库变更**：无（使用现有 notifications 表）

## 2. recurring — 周期处理

**设计意图**：自动生成周期性交易，到期提醒确认。

**触发时机**：定时任务每天凌晨检查。

**现有基础**：`recurring_transactions` 表已建好，有 `frequency`（daily/weekly/monthly/yearly）、`next_run_date`、`auto_create` 字段。

**流程**：
```
每天凌晨扫描 recurring_transactions
  ↓
next_run_date <= 今天？
  ├─ auto_create = true → 自动生成交易，更新 next_run_date
  ├─ auto_create = false → 发送提醒通知，等用户确认
  └─ 过期未确认 > 7天 → 标记为异常
```

**规则条件（conditions）**：
```json
{
  "type": "recurring_due",       // 周期交易到期
  "recurring_id": 123            // 指定周期交易ID，或省略表示全部
}
{
  "type": "recurring_overdue",   // 周期交易逾期
  "overdue_days": 7
}
```

**规则动作（actions）**：
```json
{
  "auto_create": true,           // 自动生成交易
  "notify": true,                // 同时发送提醒
  "notify_content": "明天房贷还款 ¥8000"
}
```

**新增依赖**：
- scheduler.py 扩展：每天扫描 recurring_transactions
- recurring_transactions 表（已有）
- recurring_transaction_logs 表（已有）

**数据库变更**：无

## 3. process — 后处理

**设计意图**：交易创建/修改后的自动后处理流水线。

**触发时机**：交易创建、修改、删除后实时触发（事件驱动）。

**当前已有的后处理**：
- `auto_update_credit_bill()` — 信用账单自动更新

**扩展的后处理**：
```
交易创建/修改/删除
  ↓
process 阶段规则按优先级执行：
  ├─ 信用账单更新（已有）
  ├─ 余额快照更新
  ├─ 关联账户同步（亲情卡等）
  ├─ 预算扣减
  └─ 自定义规则（用户配置）
```

**规则条件（conditions）**：
```json
{
  "type": "transaction_created",
  "account_type": "bank_credit"   // 信用账户
}
{
  "type": "transaction_created",
  "amount_min": 100000,           // 大额交易
  "category_name": "餐饮"
}
```

**规则动作（actions）**：
```json
{
  "update_credit_bill": true      // 更新信用账单
}
{
  "update_budget": true,          // 更新预算
  "budget_category": "餐饮"
}
{
  "sync_account": true,           // 同步关联账户
  "target_account_type": "alipay_balance"
}
```

**新增依赖**：
- 事件系统（交易创建/修改/删除时触发 process 阶段）
- 预算更新逻辑

**数据库变更**：无（复用现有表）

## 4. analyze — 分析洞察

**设计意图**：后台分析消费模式，生成统计级洞察。

**触发时机**：定时任务（每天/每周），分析最近N天的交易数据。

**分析维度**：
```
analyze 阶段规则：
  ├─ 消费趋势：本月支出同比/环比变化
  ├─ 分类异常：某分类支出突然增加50%以上
  ├─ 高频商户：Top10消费商户排行
  ├─ 储蓄建议：根据消费模式给出储蓄建议
  └─ 周期识别：自动发现重复消费模式
```

**规则条件（conditions）**：
```json
{
  "type": "trend_change",        // 趋势变化
  "compare": "month_over_month", // 环比
  "threshold": 0.5               // 变化幅度阈值
}
{
  "type": "category_spike",      // 分类异常
  "category_name": "餐饮",
  "threshold": 0.5
}
```

**规则动作（actions）**：
```json
{
  "generate_insight": true,
  "insight_type": "trend_alert",
  "notify": true
}
```

**与 AI 助手的区别**：
- AI 助手：交易级分析（标签建议、重复检测、周期识别）
- analyze：统计级分析（趋势、异常、排行、建议）
- 两者互补，analyze 的结果可以作为 AI 助手的输入

**新增依赖**：
- stats API 复用（已有）
- scheduler.py 扩展
- insights 表（新建，存储分析结果）

**数据库变更**：
```sql
CREATE TABLE insights (
    id          BIGSERIAL PRIMARY KEY,
    family_id   BIGINT NOT NULL REFERENCES families(id),
    type        VARCHAR(30) NOT NULL,    -- trend_alert/category_spike/savings_tip
    title       VARCHAR(200) NOT NULL,
    content     TEXT,
    data        JSONB,                   -- 分析数据
    is_read     BOOLEAN DEFAULT FALSE,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);
```

## 5. clean — 数据清洗

**设计意图**：定期检查数据质量，发现问题提醒用户。

**触发时机**：定时任务（每周），扫描最近N天的交易数据。

**检查项目**：
```
clean 阶段规则：
  ├─ 重复交易：同日同商户同金额
  ├─ 缺失字段：无分类/无商户名/无标签
  ├─ 异常金额：金额为0或负数
  ├─ 过期数据：超过1年的导入临时数据
  └─ 孤立记录：关联交易丢失
```

**规则条件（conditions）**：
```json
{
  "type": "duplicate_check",
  "window_days": 30
}
{
  "type": "missing_field",
  "field": "category_id"
}
{
  "type": "orphan_record"
}
```

**规则动作（actions）**：
```json
{
  "notify": true,
  "notify_content": "发现{n}条疑似重复交易",
  "auto_fix": false               // 是否自动修复（默认否，需用户确认）
}
```

**与 AI 助手的区别**：
- AI 助手：AI 驱动的智能检测（需要调用 LLM）
- clean：规则驱动的基础检测（纯本地逻辑，无 AI 依赖）
- clean 作为 AI 助手的补充，处理简单的数据质量问题

**新增依赖**：
- scheduler.py 扩展
- 复用 AI 助手的重复检测逻辑

**数据库变更**：无（结果通过 notifications 通知用户）

## 开发优先级

| 阶段 | 优先级 | 工作量 | 依赖 |
|------|:------:|:------:|------|
| `recurring` | P0 | 中 | recurring_transactions 表（已有） |
| `notify` | P1 | 小 | notifications 表（已有）、scheduler（已有） |
| `process` | P2 | 中 | 事件系统（需新增） |
| `clean` | P3 | 小 | 纯本地逻辑 |
| `analyze` | P4 | 大 | insights 表（新建）、stats API（已有） |

## 实现顺序建议

1. **recurring + notify**（一起做）：scheduler 扩展，同时支持周期交易和提醒通知
2. **process**：交易事件后处理流水线
3. **clean**：数据质量检查
4. **analyze**：统计级洞察（最复杂，放最后）
