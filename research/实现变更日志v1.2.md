## 一、AI 智能分类系统

### 1.1 多模型支持

新增 AI 配置模块，支持多种大模型：

| 提供商 | API 地址 | 默认模型 |
|--------|----------|----------|
| OpenAI (GPT) | https://api.openai.com/v1 | gpt-4o-mini |
| 通义千问 | https://dashscope.aliyuncs.com/compatible-mode/v1 | qwen-turbo |
| DeepSeek | https://api.deepseek.com/v1 | deepseek-chat |
| 小米 MiMo | https://token-plan-cn.xiaomimimo.com/v1 | mimo-v2.5-pro |
| 自定义 | 用户配置 | - |

### 1.2 家庭级配置

- AI 配置存储在 `families.settings.ai` 字段（JSONB）
- 同一家庭所有成员共享同一 AI 配置
- 只有 owner 和 admin 角色可以修改 AI 配置
- API Key 掩码显示（前8位...后4位）

### 1.3 AI 应用场景

**场景1：智能分类**
- 导入账单时优先使用 AI 分类
- AI 未返回结果时回退到本地关键词规则
- 批量处理：每批最多 50 条交易，减少 API 调用

**场景2：图片识别**
- 支持上传账单截图（JPG/PNG）
- AI 识别图片中的交易记录
- 支持银行卡明细、支付宝/微信账单截图、购物小票

**场景3：文件解析**
- AI 智能识别任意格式的账单文件
- 自动提取交易记录

### 1.4 相关文件

```
backend/app/
├── services/ai_service.py      # AI 服务核心（多模型调用）
├── api/ai_config.py            # AI 配置 API（5个端点）
├── api/ai_import.py            # AI 导入 API（3个端点）
└── services/categorize.py      # 分类服务（集成 AI）
```

## 二、账单导入系统重构

### 2.1 解析器模块化

将导入解析器拆分为独立模块：

```
backend/app/parsers/
├── __init__.py          # 统一导出
├── base.py              # 编码检测（detect_and_decode）
├── utils.py             # 平台识别（identify_platform_and_merchant）
├── alipay.py            # 支付宝 CSV 解析器
├── wechat.py            # 微信 CSV/Excel 解析器
├── icbc.py              # 工商银行 PDF 解析器
└── icbc_csv.py          # 工商银行 CSV/TXT 解析器
```

### 2.2 支持的文件格式

| 格式 | 来源 | 特点 |
|------|------|------|
| CSV | 支付宝 | GBK 编码，自动检测"交易来源地"字段 |
| CSV | 微信 | UTF-8 BOM，支付方式列 |
| Excel | 微信 | xlsx 格式，openpyxl 解析 |
| PDF | 工商银行 | PyPDF2 提取文本，正则解析 |
| CSV/TXT | 工商银行 | 逗号或 `^` 分隔 |
| 图片 | 任意 | AI 识别（JPG/PNG） |

### 2.3 平台识别优化

**支付宝账单**：
- 优先使用"交易来源地"字段（直接标明"淘宝"、"天猫"等）
- 回退到商户名识别

**工商银行账单**：
- 复用 `identify_platform_and_merchant` 函数
- 根据"交易场所"字段识别支付宝/微信支付
- 手机银行/网上银行 → 标记为"工商银行"平台

### 2.4 自动标签系统

导入时自动生成标签：
- 关键词规则自带标签（如"停车"→标签"停车"）
- 平台映射标签（如"淘宝"→标签"网购"）
- 标签自动创建并关联到交易

## 三、分类规则引擎

### 3.1 规则优先级

```
收入类规则（工资、奖金、利息等）
    ↓
内部转账（小荷包、零钱通、余额宝）
    ↓
红包
    ↓
保险
    ↓
餐饮、食材采购
    ↓
交通出行（打车、停车、加油、公交）
    ↓
差旅（火车、飞机、酒店）
    ↓
购物、娱乐、居住、通讯、医疗、教育
    ↓
金融理财、工作办公
```

### 3.2 分类名称与种子数据对齐

所有分类名与数据库种子数据一致：
- `工资薪酬`（非"工资薪资"）
- `服饰美妆`（非"服饰美容"）
- `通讯网络`（非"通讯"）
- `日用品`（非"购物"）

### 3.3 收入/支出分离

- 收入交易只匹配有 `category_income` 的规则
- 支出交易只匹配有 `category_expense` 的规则
- 避免收入交易误匹配到支出分类

## 四、账户层级体系

### 4.1 分组逻辑

```
平台账户（如"我的微信支付-13568810905"）
├── 微信零钱
├── 零钱通
└── 微信信用卡

银行账户（如"工商银行"）
├── 工商银行储蓄卡(尾号0726)
├── 工商银行信用卡(尾号6508)
└── 工商银行理财产品
```

### 4.2 余额显示

- 父账户（平台/银行）：显示"—"，不显示余额
- 子账户（具体产品）：显示实际余额
- 分组标题：显示子账户余额汇总

### 4.3 创建流程优化

**AccountCreateDialog 组件**：
- 三步流程：选择类别 → 填写信息 → 创建
- 支持互联网金融、银行卡、其他三大类
- 渠道类产品自动识别信用类（花呗、白条）并显示额度/账单日/还款日
- 导入时自动填充银行信息（解析"工商银行储蓄卡（0726）"）

## 七、数据库变更

### 7.1 新增字段

**payment_accounts 表**：
```sql
parent_id       BIGINT REFERENCES payment_accounts(id)
bank_id         BIGINT REFERENCES banks(id)
channel_id      BIGINT REFERENCES payment_channels(id)
linked_account_id BIGINT REFERENCES payment_accounts(id)
linked_user_id  BIGINT REFERENCES users(id)
platform_id     BIGINT REFERENCES platforms(id)
group_label     VARCHAR(50)
```

**users 表**：
```sql
settings        JSONB  -- 用户设置
```

### 7.2 新增索引

```sql
CREATE INDEX idx_pa_parent ON payment_accounts(parent_id);
CREATE INDEX idx_pa_bank ON payment_accounts(bank_id);
CREATE INDEX idx_pa_channel ON payment_accounts(channel_id);
CREATE INDEX idx_pa_platform ON payment_accounts(platform_id);
```

### 7.3 表创建顺序调整

`payment_channels` 和 `platforms` 移到 `payment_accounts` 之前创建，解决外键依赖问题。

## 九、性能优化

### 9.1 AI 批量处理

- 之前：107 笔交易逐个调用 AI → 超时（>3分钟）
- 现在：批量调用（每批 50 条）→ 约 30-80 秒完成

### 9.2 超时配置

- 前端 API 超时：10 秒 → 180 秒
- nginx 代理超时：60 秒 → 300 秒

### 9.3 分类查询优化

- 分类查询移除 `level == 1` 限制，支持所有层级
- 使用 `{c.name: c.id}` 字典加速查找
